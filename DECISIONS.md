# DECISIONS

Log of every deviation from SPEC.md, each with one line of reasoning. Never deviate silently.

- **2026-06-14 — v0.2 Dataset Export Mode: Step-Zero design decisions (proposed; awaiting approval before Phase D1).** A second, additive output mode turns media into TTS/STT **training datasets**. Full memo + citations: `docs/dataset-mode-design.md`; spec appended to `SPEC.md` ("v0.2 — Dataset Export Mode"); phases in `PROGRESS.md`. Key decisions, each web-researched then adversarially fact-checked: **(1) Delivery = a new `hearsay dataset <SOURCE>` subcommand, not a `--dataset` flag on `ingest`.** Dataset mode has a large, distinct option surface and a folder-tree output (clips + manifests), unlike `ingest`'s single markdown file; a subcommand keeps `ingest`/`--help` pristine, separates the mental models, and reuses shared plumbing (metadata, transcription, batch, feeds, youtube). Joins the existing `mcp`/`web` subcommands under `DefaultCommandGroup`. **(2) Formats = LJSpeech `metadata.csv` + `wavs/` (TTS) AND NeMo-style `manifest.jsonl` (STT), over one shared `wavs/` tree**, plus optional HF `audiofolder`. Emit LJSpeech as **`id|text|text`** (verbatim transcript duplicated), NOT `id|transcription|normalized` — verified that Coqui reads col 3 while Piper's `--dataset-format ljspeech` would misread a literal middle column as a *speaker id*; the duplicated form loads in both. JSONL `duration` is **seconds (float)** with `offset:0.0` and a manifest-relative `audio_filepath`. `--sample-rate` default 22050 (TTS-canonical), 16000 documented for ASR. **(3) Alignment = faster-whisper `word_timestamps=True` by default** (already core, MIT, zero new deps; returns `Word(word,start,end,probability)`); on Apple Silicon, merge Parakeet token timings (split on the **literal leading space**, not `▁`). One engine-agnostic `Word` adapter normalizes field names. Boundaries are coarse (~100–400 ms jitter, occasional `start>end`), so the slicer repairs inverted spans, snaps to inter-word silence, and pads edges (~100 ms). **Captions are NOT usable for clip timing** (cue-level, multi-second) — dataset mode transcribes for word timing. Better-but-optional forced alignment lives in `hearsay[align]` (WhisperX/torchaudio), with a model-license guardrail: many default alignment models are **CC-BY-NC-4.0** (ctc-forced-aligner default, torchaudio MMS_FA, even WhisperX's non-English VOXPOPULI models), so the extra prefers commercial-clean models. **(4) Audio = re-encode (never `-c copy`, which snaps to keyframes; PCM re-encode is lossless) via ffmpeg subprocess** (matches the yt-dlp pattern; no pydub/librosa). Use **input-seek** `-ss START -i SRC -t (END-START)` — frame-accurate when transcoding since FFmpeg 2.1 and far faster on long sources than output-seek. Mono `pcm_s16le`. Loudness normalization is **opt-in (default off)** — common targets (Whisper, default Coqui) don't loudness-normalize and two-pass loudnorm ~doubles work; when on, two-pass EBU R128 I=-23/TP=-1.5/LRA=7. **(5) Dependencies: core gains nothing** — numpy (via ctranslate2), PyAV `av`, and `onnxruntime` are already transitive via faster-whisper; ffmpeg/ffprobe are an existing system requirement. New **optional** extras only: `hearsay[dataset]` (light: `soundfile`, `webrtcvad-wheels` — may prove unnecessary), `hearsay[align]` (torch), `hearsay[diarize]` (`pyannote.audio`, torch, HF-gated). Excluded `pydub` (unmaintained), MFA (conda/Kaldi), `aeneas` (AGPL-3.0). **(6) Speaker problem:** without diarization, emit a **mixed-speaker** dataset (fine for STT) and warn it's unfit for single-voice TTS; with `hearsay[diarize]` + an HF token (read `HF_TOKEN`/`--hf-token`, stored in gitignored `local.env`), `--per-speaker` / `--dominant-speaker`. pyannote models are HF-gated (accept conditions on both `segmentation-3.0` and the pipeline + read token); auth failure prints exact remediation. WhisperX assigns words to speakers by **maximum temporal overlap** (not midpoint). Avoid NeMo Sortformer as default (CC-BY-NC-4.0, ≤4 speakers). **(7) Legal posture:** hearsay stays a local, user-side tool — no hosting/redistribution/download-on-behalf, ships no datasets; the **user** is responsible for media rights and voice consent (honest note in README + every `dataset_card.md`; references GDPR/BIPA/ELVIS Act/EU AI Act Art. 50, informational only). `dataset_card.md` uses HF-compatible **lowercase** license ids + HF's `unknown` default; YouTube's CC option is now **CC BY 4.0** (since ~Aug 1 2025) so we record the actual version, not a hard-coded one. **(8) Scope OUT:** no model training, no cloud upload/redistribution, no new heavy *core* dep, **no change to the markdown/JSON engine** (the only existing-file touch is an opt-in `word_timestamps` capture in `transcribe.py`, default off → unchanged behavior/schema), no heavier GUI. All current tests must keep passing; tests stay offline.
- **2026-06-14 — Maintenance pass + version bump to `0.2.0` (post-merge audit fixes).** After merging the Parakeet engine + web UI, a four-lens audit (deps vs PyPI, code bugs, doc accuracy, packaging) drove these fixes. **Bugs:** (1) Parakeet reported `duration_s` as the last *spoken* segment's end — wrong (too short, or `00:00:00` for speechless audio) vs the Whisper path's true media length; now takes the real length from the chunk callback (`max(audio_total_s, last_seg_end)`). (2) **Model-download robustness:** large weights (Parakeet v3 is ~2.5 GB) died at huggingface_hub's 10s default read-timeout on slower links ("read operation timed out"); a new `_ensure_download_timeout()` raises the floor to 60s — setting the env var *and* the live `constants.HF_HUB_DOWNLOAD_TIMEOUT` (frozen at import, read live), honoring any higher user value, and never touching the offline path. **Docs:** the Parakeet model size was stated as "~600 MB" in README + the code's error hint — actually ~2.5 GB (`model.safetensors` = 2,508,288,736 bytes); corrected both. `--version` moved out of the `ingest` option list (it's a top-level flag). `mcp_server` docstring now lists `HEARSAY_VAD` + `HEARSAY_PARAKEET_MODEL`. **Packaging:** added `classifiers` (Python 3.11/3.12 only — matches CI), `keywords`, `[project.urls]` (Homepage/Repository/Issues → the GitHub repo), and `maintainers`; this is what actually configures the homepage the 0.1.0 launch note below referred to (it was not set on the published 0.1.0). **Deps:** all current vs PyPI; bumped the dev-only `pytest` floor `9.0.3 → 9.1.0` and re-locked. Version `0.1.0 → 0.2.0` (minor: two backward-compatible features). NOT yet published — publishing 0.2.0 to PyPI is a separate, credentialed step.
- **2026-06-14 — Added an optional local web UI (`hearsay web`); overrides the SPEC "No GUI" non-goal (contributed; PR split 2/2).** SPEC's non-goals state "No GUI". **Project-owner decision: ship a GUI _in addition to_ the CLI, not instead of it** — users pick whichever they prefer, and the CLI/MCP paths are entirely untouched. `hearsay web` starts a standard-library-only (`http.server`) local server with a single embedded HTML page; there is **no new runtime dependency** (only a per-file ruff `E501` ignore for the embedded HTML/CSS/JS asset). It wraps the existing pipeline for single YouTube URLs and file uploads (playlists/feeds stay CLI-only, with a friendly in-UI hint). It binds `127.0.0.1` by default, so it stays a local, user-side tool and doesn't re-host content. Lands stacked on the Parakeet engine PR (its model picker offers `auto`/`parakeet`). From contributor @Nesbesss's PR #1, split out from the engine change for focused review.
- **2026-06-14 — Added an optional Parakeet (MLX) transcription engine; default model `small` → `auto` (contributed; PR split 1/2).** SPEC pins faster-whisper as the CPU fallback and asks that every new dependency be justified here. faster-whisper stays the portable default and remains the only engine on Linux/Windows/Intel Mac; NVIDIA **Parakeet-TDT on Apple MLX** is added as an *opt-in* extra (`hearsay[parakeet]`, gated to `sys_platform=='darwin' and platform_machine=='arm64'`), giving ~3× faster local transcription on Apple Silicon at comparable accuracy. The new default `--model auto` resolves to Parakeet when the extra is importable, else `whisper-small` — so behaviour is identical anywhere the extra isn't installed (an explicit `--model parakeet` off Apple Silicon fails loudly with a hint, never a silent downgrade). `parakeet-mlx` is the only new dependency, optional and platform-gated, so a plain install stays light and the captions path still pays no import cost (lazy imports preserved). `TranscriptionResult` gains a `method` label so documents are tagged with the real engine (`parakeet-tdt-0.6b-v3` / `whisper-small`) instead of a hardcoded `whisper-` prefix. From contributor @Nesbesss's PR #1, split into engine-only (this PR) + web UI (separate PR) for focused, independent review.

- **2026-06-13 — Post-launch: added a `--vad/--no-vad` flag (default on).** Real-world testing on a captionless song surfaced that the hardcoded `vad_filter=True` discarded all the music as "non-speech", producing a near-empty transcript (1 word). VAD-on is correct for the core speech use case (podcasts/talks/meetings — it skips silence and curbs hallucination), so it stays the default; `--no-vad` (and `HEARSAY_VAD=0` for the MCP server) lets music/songs be transcribed. Music transcripts are still approximate (Whisper is a speech model); README documents this. Verified live: talking ad (clean) and the song (lyrics recovered with `--no-vad`).

- **2026-06-13 — Project is named `hearsay`, not `earshot`.** The PyPI check (`curl https://pypi.org/pypi/earshot/json`) returned HTTP 200: `earshot` is taken by an active package (Python bindings for a Rust voice-activity-detection library, v0.2.0) in our exact domain, so even name-squatting nearby would be confusing. Five free alternatives were verified against PyPI (all returned 404): `hearsay`, `soundbite`, `transcrawl`, `audioscribe`, `mediamark` (`overhear`, `earworm`, `echolog` were taken). Picked **hearsay**: a real, memorable word that describes the product literally — speech someone heard, passed along in written form — and reads well as a command (`hearsay <url>`). Used consistently everywhere; only SPEC.md keeps the original `earshot` wording because it is verbatim.

- **2026-06-13 — Phase 4: MCP `ingest_url` is single-video; the SDK is an optional extra; server configured by env.** `ingest_url(url, transcribe?, lang?)` and `ingest_file(path)` each return one markdown string (so `ingest_url` handles a single YouTube video, with the same captions→whisper fallback as the CLI — not playlists/feeds, which are multi-item). - **2026-06-13 — Phase 3 gate review (independent 6-lens workflow): acceptance/spec/JSON/offline passed; one blocker + minors fixed.** Confirmed blocker: two feed episodes whose titles slugify to the same stem silently overwrote each other's output (and the summary falsely showed both ✓). Fixed with `batch.ensure_unique_slugs`, applied to every batch before selection (first keeps the base slug, collisions get `-2`, `-3`…). Minors fixed: `extract_playlist_id` now parses the URL and requires the path to be exactly `/playlist` (a `watch?...&next=/playlist...` URL no longer misroutes); `download_episode` checks `Content-Length` and rejects a truncated download; `--output-dir` creation maps `OSError` to a friendly `OutputWriteError`; the `--json` sidecar no longer clobbers the markdown when `-o` ends in `.json` (sidecar becomes `name.json.json`); `--limit < 1` is rejected; `_duration_seconds` clamps negatives to 0. The batch CLI was refactored to pass an explicit frozen `_Options` dataclass instead of `locals()`, so a renamed option can't become a KeyError traceback.
- **2026-06-13 — Phase 3: source routing extended to playlists and feeds; `--latest` = first/newest item.** CLI detection order is: existing local file → canonical `/playlist?list=` URL → single video URL → any other http(s) URL tried as a podcast RSS feed → otherwise a (missing) local path. A `watch?v=...&list=...` URL is a single video, not a playlist. `--latest` selects item index 0 (newest for feeds, first for playlists); `--episode N` is 1-indexed; `--all` ingests all, capped by `--limit`. With no selection flag, a batch source lists its items in a rich table and exits without ingesting.
- **2026-06-13 — Phase 3: podcast episode audio downloads via stdlib urllib, not yt-dlp.** Episode enclosures are direct media URLs; urllib (with a User-Agent and timeout) is simpler and more reliable for them than yt-dlp's format selection, and adds no dependency. yt-dlp is still used for the YouTube `--transcribe` download.
- **2026-06-13 — Phase 3: `--output-dir` (default `./hearsay-out/`) is created if missing; single-file `-o` is not.** Batch ingestion's whole purpose is to populate a folder, so the output dir is `mkdir -p`'d. A single `-o` path still errors if its parent is missing (a typo guard), per the Phase 1 decision.
- **2026-06-13 — Phase 3: the canonical JSON-Schema serializer lives in `hearsay.models.transcript_schema_json()`.** Both `scripts/export_schema.py` and the sync test import it, so `docs/schema.json` has a single source of truth and no `sys.path` hacks. The `method` field documents the `captions` / `captions-auto` / `whisper-<model>` values.
- **2026-06-13 — Phase 2 gate review (independent 5-lens workflow): acceptance/spec/offline passed, no confirmed blockers; minors fixed.** The one claimed blocker — a local file path containing a YouTube host substring being routed to yt-dlp — was downgraded to minor (contrived, fails loudly) but fixed anyway: `_produce_document` now routes an existing local file before URL extraction. Other fixes: whisper `seg.end` is clamped to `>= start_s` (and `Segment` construction moved outside the decode try/except, so a model-invariant slip no longer masquerades as a "bad file" error); `download_audio` selects the largest non-sidecar file instead of an arbitrary `iterdir()[0]`; the stale "transcription lands in Phase 2" no-captions hint now points at `--transcribe`. Accepted local-file extensions are a deliberate superset of the spec's four (adds aac/flac/ogg/opus/webm/mkv/mov — all PyAV-decodable). `--lang` now defaults to unset (None): captions still default to English (`language or "en"`), while transcription auto-detects unless `--lang` is given, so `--lang en` genuinely forces English on both paths.
- **2026-06-13 — Phase 2: no explicit ffmpeg extraction step for local files.** SPEC says "extract audio via ffmpeg if needed". faster-whisper decodes audio/video directly via its bundled PyAV (libav), so mp3/m4a/wav/mp4/webm are read without shelling out to ffmpeg — "if needed" is satisfied by it not being needed. ffmpeg stays a documented requirement (some yt-dlp format merges need it) but is not on the hot path. The YouTube `--transcribe` download requests `bestaudio[ext=m4a]/bestaudio/best`, avoiding a re-encode (and thus ffmpeg) in the common case.
- **2026-06-13 — Phase 2: faster-whisper is a core dependency, lazily imported.** It is heavy (ctranslate2, onnxruntime, PyAV, numpy), but the spec lists it as the core transcription fallback and Phase 2 acceptance requires it, so it is a main dependency rather than an optional extra. To keep the captions-only path fast, `faster_whisper` is imported inside `transcribe.py` functions, not at module top — `hearsay <url>` (captions) never pays the import cost.
- **2026-06-13 — Phase 2: the test audio fixture is OS-TTS-generated.** `tests/fixtures/sample.wav` (4.7s) was produced by macOS `say` + ffmpeg, not a third-party recording — so there is no licensing concern (satisfies the spec's "public-domain" intent) and the repo carries no copyrighted audio. The whisper integration test loads the model with `local_files_only=True`, so it runs offline when the model is cached and skips cleanly otherwise (CI caches the model or skips).
- **2026-06-13 — Phase 2: no-captions YouTube videos now auto-fall-back to whisper.** In Phase 1 a captionless video produced a friendly "transcription lands in Phase 2" error; that behavior is now replaced by automatic local transcription with a notice. The Phase 1 test asserting the old message was removed and replaced with `test_auto_fallback_to_whisper_when_no_captions`.
- **2026-06-13 — Phase 1 gate review (independent 5-lens workflow) hardened the I/O path.** Acceptance, spec, core-code, and offline-test lenses all passed. One confirmed blocker fixed: file-write failures (bad `-o` path, target is a directory) now raise `OutputWriteError` with a hint instead of a traceback. Two output-format bugs (downgraded to minor but fixed anyway, since the spec calls output the core feature): the YAML escaper now handles newlines/tabs/control chars, and `#`/`##` headings are collapsed to one line — so a crafted title can't break frontmatter or inject markdown structure. Also fixed several minors: `parse_metadata` raises `MetadataError` (not `KeyError`) on a missing `id`; the yt-dlp subprocess decodes UTF-8 explicitly (Windows-safe); `extract_video_id` rejects over-long ids rather than truncating; section span titles use the true max `end_s`; `format_timestamp` tolerates NaN/inf. The noise-cue filter was tightened twice: the original dropped any short bracketed snippet (losing real speech like `(I think so)`), and a too-narrow rewrite then *kept* music cues like `[ominous music plays]` — the final rule drops a wrapped cue iff it contains a conservative sound keyword (music/applause/laughter/...), which drops the cues while keeping `[for all your hard work]`. Added `tests/conftest.py` blocking non-loopback network during tests so the offline-CI guarantee is self-enforcing.
- **2026-06-13 — `method` frontmatter value is `captions` (manual) or `captions-auto` (auto-generated).** The spec's format line shows `method: "captions" | "whisper-small"`. Auto-generated captions are materially lower quality than human ones, and a RAG/agent consumer should be able to tell them apart — so the captions path emits two values. This follows the spec's own pattern of encoding the variant inside the method string (whisper-**small**); the whisper path will likewise be `whisper-<model>` (e.g. `whisper-small`, matching the spec example exactly).
- **2026-06-13 — CLI is a single Typer command for Phase 1–3, not a command group.** A group with an `invoke_without_command` callback misparses options given after the positional `SOURCE` (`hearsay <url> --output x` fails with "No such command --output"). A single command keeps option order natural. The `mcp` subcommand in Phase 4 will convert this to a group and move `--version`/source handling onto a callback at that point.
- **2026-06-13 — Paragraph-grouping algorithm: pause-primary design chosen via a judge panel.** This is the core feature, so three independent implementations (pause-primary, sentence-primary, scored-boundary) were built against the real fixtures and scored by a 3-lens panel (readability, spec conformance, robustness). The sentence-primary candidate was lost to a mid-run model switch; of the two survivors the panel voted 2–1 for the pause-primary design: it held 100% of paragraphs inside the 40–120 word budget on both fixtures (the scored-boundary rival shipped 123- and 136-word paragraphs, violating the cap the spec names), and its dangling-word penalty avoided mid-phrase cuts like splitting "large | language models" that the rival made repeatedly on unpunctuated captions. The robustness judge preferred the rival only because the winner had two cheap-to-fix bugs (an IndexError on empty segments, a degenerate-param collapse). Both were fixed and the best ideas from the rival were grafted in: a discourse-marker begin-bonus, a two-sided boundary check, an ellipsis tier, abbreviation demotion, and a slightly lower target size. All verified by tests.
